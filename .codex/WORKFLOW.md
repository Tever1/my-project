# Codex ↔ Claude — Гибридный workflow

Этот документ описывает как мы работаем втроём: пользователь, Claude, Codex.

---

## Распределение ролей

| Роль | Кто | Что делает |
|---|---|---|
| **Заказчик** | Пользователь | Ставит задачи, принимает финальный результат, мерджит, пушит |
| **Архитектор/Ревьюер** | Claude | Планирует, пишет ТЗ, проверяет работу Codex, обновляет CLAUDE.md, общается с пользователем |
| **Исполнитель** | Codex | Делает черновую работу строго по ТЗ, пишет отчёт |

**Claude НЕ пишет production-код руками** (кроме `.codex/*` и документации).
Его задача — думать и проверять.

---

## Полный цикл одной задачи

```
1. Пользователь: "сделай X"
       ↓
2. Claude: планирует, оценивает сложность (simple / complex)
       ↓
3. Claude: пишет .codex/tasks/NNN-X.md
       ↓
4. Claude: добавляет запись в .codex/STATUS.md (активный таск)
       ↓
5a. SIMPLE: Claude сам запускает `codex exec` — индикация в чате 🤖
5b. COMPLEX: Claude говорит "переходи в Codex Desktop, открой .codex/tasks/NNN-X.md" 🖥️
       ↓
6. Codex: делает работу, пишет .codex/reports/NNN-X.md
       ↓
7. Claude: читает отчёт + git diff, валидирует
       ↓
8a. ОК: Claude сообщает пользователю "готово", переносит запись в историю STATUS.md
8b. НЕ ОК: Claude пишет TASK-NNN.1 с правками, возврат на шаг 5
       ↓
9. Пользователь: ревьюит, коммитит, пушит
```

---

## Критерии simple / complex

### SIMPLE — Claude запускает `codex exec` сам 🤖

- Один-два файла в whitelist
- Чёткое механическое изменение (rename, type fix, добавить поле, удалить мёртвый код)
- Нет архитектурных решений
- Не трогает `server.mts` и игровую логику
- Ожидаемое время Codex < 5 минут

**Примеры:** переименование переменной во всех файлах, добавление i18n-строки,
fix линт-ошибки, добавление нового пресета цвета.

### COMPLEX — пользователь запускает в Codex Desktop 🖥️

- 3+ файла или новый компонент
- Затрагивает игровую логику или socket.io
- Есть архитектурные решения (выбор подхода)
- Нужно видеть процесс в реальном времени
- Ожидаемое время Codex > 5 минут

**Примеры:** новая фича, рефакторинг handler'ов, изменение типов в `game.ts`,
новый glass-компонент.

## Индикация в чате

Когда Claude запускает Codex сам, он **обязан** показать в чате:

```
🤖 Запускаю Codex (TASK-NNN: <название>)
   Файлы: src/foo/bar.ts, src/foo/baz.ts
   Ожидаемое время: ~3 минуты
   Команда: codex exec .codex/tasks/NNN-name.md
```

После завершения:

```
✅ Codex завершил TASK-NNN
   Отчёт: .codex/reports/NNN-name.md
   Diff stat: <N файлов, +X -Y>
   Проверяю результат...
```

Когда Claude передаёт пользователю на complex-таск:

```
🖥️ Этот таск сложный — нужно запустить вручную в Codex Desktop.

Открой Codex Desktop и скорми ему файл:
   .codex/tasks/NNN-<name>.md

Я буду ждать пока ты не скажешь что Codex закончил
(или появится .codex/reports/NNN-<name>.md).
```

## Защита от коллизий

1. **STATUS.md = источник истины.** Перед любой работой — проверка.
2. **Whitelist файлов в task-spec'е** — Codex не выходит за их пределы.
3. **Claude не редактирует production-код** — только `.codex/*`, `CLAUDE.md`,
   `docs/*`. Если нужно срочно поправить что-то — пишет TASK для Codex.
4. **Один активный таск на файл.** Если нужно параллельно — разные файлы.
5. **Codex не коммитит сам.** Коммитит пользователь (или Claude после ревью
   с явного разрешения).

---

## Что делать если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Codex вышел за whitelist | Реверт через `git checkout -- <files>`, пишем TASK-NNN.1 с уточнениями |
| Codex сломал build | Читаем отчёт, ищем что он сделал, реверт + новый таск |
| STATUS.md рассинхронизировался | Очищаем активные, начинаем заново |
| Conflict в редактируемых файлах | Это значит правило "один таск на файл" нарушено — реверт обоих |

## Файлы и папки

```
.codex/
  AGENTS.md          ← правила для Codex (синхронизирован с CLAUDE.md)
  WORKFLOW.md        ← этот файл
  STATUS.md          ← шина состояния (активные/завершённые таски)
  config.toml        ← настройки Codex CLI
  hooks/, hooks.json ← Codex hooks
  skills/            ← Codex skills
  tasks/
    _TEMPLATE.md     ← шаблон task-spec'а
    NNN-name.md      ← конкретные задания
  reports/
    _TEMPLATE.md     ← шаблон отчёта
    NNN-name.md      ← отчёты Codex
  archive/           ← завершённые таски (опционально, для истории)
```

---

## Нумерация тасков

- Простая инкрементная: `001`, `002`, `003`, ...
- При итерациях по одному таску: `001`, `001.1`, `001.2`, ...
- При параллельных задачах разные номера никогда не пересекаются.
