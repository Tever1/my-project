# Локальная генерация в админке

Кнопки генерации используют отдельный короткий запуск установленного Codex CLI,
а не текущий чат. Вход — через ChatGPT; запросы расходуют лимиты аккаунта.
OpenRouter и автоматического перехода к другому провайдеру в этих маршрутах нет.
Это локальная интеграция для Mac, не решение для публичного хостинга.

## Подключение

1. Установить Codex CLI и выполнить вход через ChatGPT (`codex login`).
2. Сервер должен видеть CLI в PATH. При необходимости задать
   `ADMIN_CODEX_BIN` абсолютным путём в окружении сервера.
3. Открыть `/admin` на localhost. Скопировать ключ из
   `data/codex-admin-key.txt` в поле «Ключ администратора» и нажать
   «Запомнить на 30 дней». Вход сохраняется между вкладками и перезапусками
   этого браузера через подписанную HttpOnly/SameSite=Strict cookie.
   Сам ключ в sessionStorage/localStorage не сохраняется.
   Файл создаётся первым запросом к защищённому маршруту; доступ к файлу — 0600.
   Не отправлять ключ игрокам и не хранить его в Git.
4. Модель по умолчанию — `gpt-6-astra`; `ADMIN_CODEX_MODEL` позволяет изменить её
   при запуске сервера. Пользовательская конфигурация CLI не подмешивается.

Слова, локации, замена вопросов/элементов, проверка вопросов и промпты идут через
текстовый Codex. Фон запрашивается у встроенного генератора изображений Codex.
Отдельный OpenAI API key не используется. Только проверка достоверности включает
live web search: модель должна открыть источники, указать прямые ссылки и отметить
неподтверждённые факты. У остальных генераторов поиск отключён.

## Ограничения и безопасность

### Отчёты проверки достоверности

Рядом с кнопкой проверки есть «Отчёты» — история выбранного квиза с датами,
результатами и исходными проверенными вопросами. Общие квизы разделены по
теме/сложности, специальные — по ID. Проверки отдельных вопросов тоже сохраняются.
История хранится на серверном Mac в `data/quiz-check-reports/`, не в браузере;
просмотр не запускает модель. Доступ защищён тем же входом администратора.
Отчёты относятся к снимку вопросов на момент проверки, а не к последующим правкам.
Если запись не удалась, текущий результат показывает предупреждение о сохранении.
Отчёты, потерянные до появления истории, автоматически восстановить нельзя.

### Общие ограничения

- Один запрос генерации одновременно на процесс сервера. Текст — до 3 минут,
  фон — до 8 минут. Повторный запрос получает 429; сбой — явную ошибку.
- CLI запускается без shell-интерполяции, в отдельной временной папке,
  с read-only sandbox, выключенными shell и multi-agent; web search разрешён
  только для проверки достоверности.
  Ключи сторонних API из окружения сервера не передаются.
- Символьная ссылка CLI раскрывается: рядом с настоящим бинарником должен быть
  компонент `codex-code-mode-host`, необходимый встроенному генератору.
- PNG принимается только из временной папки задания или `CODEX_HOME/generated_images`,
  проверяются свежесть, размер и возможность декодирования. Файлы генератора
  остаются в его локальном архиве; временная папка задания удаляется.
- Ключ защищает генерацию и маршруты game-item/quiz-item. Остальные admin API
  по-прежнему не имеют полноценной авторизации. Не публиковать админку в интернете.
- Cookie привязана к браузеру и hostname, не аппаратному MAC-адресу.
  localhost и LAN IP требуют отдельных входов. Очистка cookie, истечение 30 дней
  или «Выйти» требуют повторного ввода ключа. Статус проверяется при открытии.
  Cookie действует на `/api/admin`, без Domain; Secure включён при HTTPS.
  На локальном HTTP Secure выключен. Использовать localhost: передача ключа
  или сессии по HTTP в LAN не шифруется.
- Cookie-запросы требуют совпадения Origin и адреса назначения. Вход с ключом
  остаётся доступен для локальных инструментов. «Выйти» удаляет cookie браузера,
  но не отзывает ранее скопированную сессию: для отзыва всех сессий заменить
  локальный ключ. Смена ключа делает существующие подписи недействительными.
- Старый `/api/admin/run` отключён (410); скрипты вне админки не мигрировались.
- Перед публикацией требуется отдельное ревью безопасности. Browser QA,
  production build, commit и push выполняются только с разрешения владельца.
