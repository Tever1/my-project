# Локальная генерация в админке

Кнопки генерации используют отдельный короткий запуск установленного Codex CLI,
а не текущий чат. Вход — через ChatGPT; запросы расходуют лимиты аккаунта.
OpenRouter и автоматического перехода к другому провайдеру в этих маршрутах нет.
Это локальная интеграция для Mac, не решение для публичного хостинга.

## Подключение

1. Установить Codex CLI и выполнить вход через ChatGPT (`codex login`).
2. Сервер должен видеть CLI в PATH. При необходимости задать
   `ADMIN_CODEX_BIN` абсолютным путём в окружении сервера.
3. Открыть `/admin` на localhost. Скопировать ключ из
   `data/codex-admin-key.txt` в поле «Ключ администратора» и нажать
   «Запомнить на 30 дней». Вход сохраняется между вкладками и перезапусками
   этого браузера через подписанную HttpOnly/SameSite=Strict cookie.
   Сам ключ в sessionStorage/localStorage не сохраняется.
   Файл создаётся первым запросом к защищённому маршруту; доступ к файлу — 0600.
   Не отправлять ключ игрокам и не хранить его в Git.
4. Модель по умолчанию — `gpt-6-astra`; `ADMIN_CODEX_MODEL` позволяет изменить её
   при запуске сервера. Проверка достоверности Quiz использует меньшую модель
   `gpt-5.6-terra` по умолчанию; только для неё `ADMIN_CODEX_FACTCHECK_MODEL`
   переопределяет модель. Пользовательская конфигурация CLI не подмешивается.

Слова, локации, замена вопросов/элементов, проверка вопросов и промпты идут через
текстовый Codex. Фон запрашивается у встроенного генератора изображений Codex.
Отдельный OpenAI API key не используется. Только проверка достоверности включает
live web search: модель должна открыть источники, указать прямые ссылки и отметить
неподтверждённые факты. Проверка достоверности Quiz работает только с русским
текстом вопроса и четырьмя русскими ответами: `questionEn` и `option.en` в модель
не передаются и не меняются её выводом. У остальных генераторов поиск отключён.

## Ограничения и безопасность

### Квизы, персонажи и дискета

Во вкладке «Квизы» можно создать тематический квиз с ru/en названием, группой
темы, номером и фоном; добавить/редактировать вопросы или создать 1–10 через Codex.
Новые вопросы не считаются проверенными. Проверка списка идёт блоками по 2;
перед запуском показывается количество модельных запросов и предупреждение о лимитах.
Слева — готовые тематические квизы и категории общего банка со счётчиками
вопросов по сложности. При повторной проверке UI и сервер исключают вопросы,
уже подтверждённые Codex с источниками для текущей версии. Если все вопросы
подтверждены, запуск Codex не происходит. Ручное утверждение владельца само
по себе не является модельным подтверждением и не исключает вопрос из проверки.

Индикаторы: «Нужна проверка», «Есть замечания», «Проверен Codex» / «Проверен
Codex · RU», «Утверждён владельцем». Русская проверка хранится с явной областью
`scope=ru` и русской подписью: правки английского текста её не снимают, а правки
`questionRu`, русских ответов или `correctIndex` снимают. Старые двуязычные
проверки без области остаются читаемыми и работают по прежней полной подписи.
Автоматическое подтверждение — только положительный структурированный verdict
с прямыми https-источниками и совпадением текущей версии вопроса с проверенной.
При замечаниях вопрос с источниками можно утвердить вручную; отчёт Codex остаётся
видимым. Правка вопроса/ответов снимает проверку; новая модельная проверка снимает
прежнее ручное утверждение. Отчёты имеют историю и привязку к ID вопроса.

Во вкладке «Игры» → «Кто я?» можно добавлять, редактировать и удалять ru/en персонажей.
Также можно создать 1–10 персонажей через Codex. Новые персонажи не проверены:
галочку рядом с именем ставит владелец вручную. Изменение имени или перевода
снимает галочку; сохранение неизменённого имени её сохраняет.
Alias, Crocodile и Spy показывают слова единым вертикальным списком с ручными
галочками, поиском и фильтром непроверенных. У Spy отдельно подписаны слова
рисования и места/слова обсуждения. Эти отметки тоже сохраняются через дискету;
они не удаляют непроверенные слова и не меняют порядок/состав runtime-банков.
Существующие отдельные legacy-генераторы слов не переводятся на новый банковый
протокол этой итерацией. Индексированные игровые банки остаются исходными.
Эти действия, правки/удаления вопросов и квизов записываются только в общий
`data/admin-content-draft.json`. Переключение вкладок или перезагрузка не теряют
сохранённые черновые правки. Текст в ещё не отправленной форме нужно сначала
применить кнопкой «Сохранить в черновик».

Дискета сверху сохраняет все накопленные действия в `content/game-content.json`.
Перед записью сохраняется резервная копия `data/content-backups/`.
Конфликт версий блокирует перезапись чужих правок. При пустом playable общем
банке или менее 12 персонажах сохранение отклоняется. Пустой тематический квиз
можно сохранить, но он не предлагается игрокам до добавления вопросов.
Обычный lock-файл `data/admin-content.lock` может остаться после аварии процесса:
перед его ручным удалением убедитесь, что сохранение сейчас не выполняется.

Игры читают опубликованный каталог через `/api/content` без check/approval metadata.
Новый Quiz / Who Am I старт обновляет банк; активные очереди вопросов и назначенные
персонажи не заменяются публикацией. Исходные TypeScript-банки не перезаписываются:
они остаются fallback до первого сохранения. JSON — настоящий игровой файл,
не временная копия для админки, и может версионироваться в Git.
Прежние `quiz-overrides` / `quiz-reviews` импортируются в черновик, а не автоматически в игру.

### Папки и выбор фонов

С TASK-533 игровой формат — WebP: вся вкладка «Фоны» и выбор фона квиза
показывают только `.webp`. Существующие PNG перенесены в
`public/backgrounds/sources/`, включая прежние тематические копии. Они сохранены
без перекодирования; ссылки на используемые WebP не менялись.

При сохранении новой генерации один PNG от Codex записывается в
`public/backgrounds/sources/<theme>/<name>.png`, из него создаётся WebP quality 80
с той же шириной и высотой в `public/backgrounds/<theme>/<name>.webp`.
Отдельного второго вызова модели нет. В игру возвращается WebP URL. Оба имени
защищены от перезаписи; при ошибке второго файла удаляется только созданный
этим запросом первый файл. Проверяются декодирование, формат и размеры PNG.
Новые настройки квиза и дискета требуют WebP; старый PNG-фон в черновике
не заменяется молча — перед синхронизацией нужно выбрать его WebP-версию.

Готовые изображения сгруппированы в `public/backgrounds/marvel/` и
`public/backgrounds/harry-potter/`; корневые оригиналы сохранены для совместимости
с прежними URL. Галерея скрывает дубли этих корневых aliases и фильтруется по папкам.
Новые сгенерированные фоны сохраняются в папке выбранной темы.
Раздел «Не привязаны к квизу» также показывает только WebP. PNG-исходники
не входят в игровую библиотеку и не показываются в этой вкладке.

В форме квиза файловая строка открывает системный диалог браузера. Выберите файл
из `public/backgrounds`; начальную папку native chooser браузер задаёт сам, код
не может принудительно указать абсолютный путь Mac. Содержимое выбранного файла
сверяется с библиотекой по SHA-256, а не только имени. На insecure LAN без Web Crypto
используйте расположенный рядом список папок библиотеки. Произвольный внешний файл
не загружается этой строкой: это выбор уже готового библиотечного фона.

Сохранение новых изображений / удаление файлов фона — отдельные явные действия,
не черновик вопросов. Используемый опубликованным или черновым квизом фон удалить
нельзя. Эти маршруты теперь также требуют admin-входа; PNG-save имеет отдельный
лимит тела 12 MB и проверку PNG/размеров. Admin остаётся локальным инструментом,
не production-ready публичной панелью.

### Отчёты проверки достоверности

Рядом с кнопкой проверки есть «Отчёты» — история выбранного квиза с датами,
результатами и исходными проверенными вопросами. Общие квизы разделены по
теме/сложности, специальные — по ID. Проверки отдельных вопросов тоже сохраняются.
История хранится на серверном Mac в `data/quiz-check-reports/`, не в браузере;
просмотр не запускает модель. Доступ защищён тем же входом администратора.
Отчёты относятся к снимку вопросов на момент проверки, а не к последующим правкам.
Если запись не удалась, текущий результат показывает предупреждение о сохранении.
Отчёты, потерянные до появления истории, автоматически восстановить нельзя.

### Предлагаемые исправления вопросов

Гарри Поттер проверяется исключительно по восьми основным фильмам. При
расхождении с книгой фильм имеет приоритет; книжные источники сами по себе
не подтверждают ответ. Правило действует также для генерации и замены.
Старые отметки без `harry-potter-films-v1` требуют перепроверки по фильмам,
включаются в новую проверку списка и не дают применить старое исправление.

После новой проверки неточного вопроса Codex предлагает исправленный русский
вопрос, все четыре русских ответа, правильный вариант, объяснение и источники.
Английский текст текущего вопроса сохраняется без изменений и не переписывается
моделью.
Исправленный вариант проверяется в этом же запросе. «Исправить» доступна,
только когда он подтверждён источниками; неподтверждённый вариант можно
рассмотреть, но он не получает автоматический verified.
Нажатие применяет именно сохранённое предложение, без второй генерации, и
отмечает новую версию «Проверен Codex». ID, тема, сложность и время не меняются.
Старое предложение не применяется после редактирования вопроса или обновления
черновика другой вкладкой. Первоначальный отчёт и предложение остаются в истории.
Правка и статус записываются в игровые файлы только после дискеты.
У старых отчётов предложений нет: при необходимости нужна новая проверка.

### Прогресс и замена неудачного вопроса

Текущая проверка показывает «Проверено X из Y» и шкалу. Счётчик обновляется
после каждого ответа сервера (до 2 вопросов в блоке), а не по таймеру.
При ошибке показывается остановка с достигнутым прогрессом. Пропущенные ранее
подтверждённые вопросы считаются отдельно. «Прошли проверку» включает вопросы
с замечаниями; это не то же самое, что «Подтверждено».

После актуальной проверки с замечаниями или неподтверждённым verdict доступна
«Заменить вопрос»: один запрос Codex создаёт другой вопрос в той же категории
или тематическом квизе, сохраняя сложность и время. Старый вопрос заменяется
в черновике на той же позиции, новый получает другой ID и не наследует проверку,
предложение исправления или ручное утверждение. Его нужно проверить заново.
Прямые текстовые дубли банка отклоняются; фактическая тематическая точность
ответа модели требует просмотра/проверки. При ошибке или конфликте старый вопрос
не удаляется. В опубликованную игру замена попадёт только через дискету.

### Общие ограничения

- Один запрос генерации одновременно на процесс сервера. Текст — до 3 минут,
  фон — до 8 минут; только проверка достоверности идёт без фиксированного
  дедлайна. Повторный запрос получает 429; сбой — явную ошибку.
- CLI запускается без shell-интерполяции, в отдельной временной папке,
  с read-only sandbox, выключенными shell и multi-agent; web search разрешён
  только для проверки достоверности.
  Ключи сторонних API из окружения сервера не передаются.
- Символьная ссылка CLI раскрывается: рядом с настоящим бинарником должен быть
  компонент `codex-code-mode-host`, необходимый встроенному генератору.
- PNG принимается только из временной папки задания или `CODEX_HOME/generated_images`,
  проверяются свежесть, размер и возможность декодирования. Файлы генератора
  остаются в его локальном архиве; временная папка задания удаляется.
- Ключ защищает генерацию и маршруты game-item/quiz-item. Остальные admin API
  по-прежнему не имеют полноценной авторизации. Не публиковать админку в интернете.
- Cookie привязана к браузеру и hostname, не аппаратному MAC-адресу.
  localhost и LAN IP требуют отдельных входов. Очистка cookie, истечение 30 дней
  или «Выйти» требуют повторного ввода ключа. Статус проверяется при открытии.
  Cookie действует на `/api/admin`, без Domain; Secure включён при HTTPS.
  На локальном HTTP Secure выключен. Использовать localhost: передача ключа
  или сессии по HTTP в LAN не шифруется.
- Cookie-запросы требуют совпадения Origin и адреса назначения. Вход с ключом
  остаётся доступен для локальных инструментов. «Выйти» удаляет cookie браузера,
  но не отзывает ранее скопированную сессию: для отзыва всех сессий заменить
  локальный ключ. Смена ключа делает существующие подписи недействительными.
- Старый `/api/admin/run` отключён (410); скрипты вне админки не мигрировались.
- Перед публикацией требуется отдельное ревью безопасности. Browser QA,
  production build, commit и push выполняются только с разрешения владельца.
