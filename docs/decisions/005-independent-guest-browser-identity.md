# Independent guest browser identity

## Context

Для локальной party-game часто открывают несколько телефонов в одном браузере
или на одном компьютере. Когда guest ID хранился в общем `localStorage`, все
окна воспринимались как один игрок; удалённое имя также могло самопроизвольно
возвращаться из сохранённой identity.

## Decision

Guest player ID хранится в `sessionStorage` через
`src/lib/guest-player-id.ts`. Зарегистрированный mock-user по-прежнему может
использовать `localStorage`. Для ручного QA каждое видимое Chrome-окно
запускается с отдельным `user-data-dir` и размером 390×844.

## Reason

`sessionStorage` изолирует вкладки/сессии, не требуя серверной регистрации, а
отдельный профиль гарантирует полную независимость cookies/storage при QA.

## Alternatives

- Общий guest ID в `localStorage` — отвергнут: окна становятся одним игроком.
- Случайный ID при каждом render — отвергнут: ломает reconnect и стабильную
  идентичность вкладки.
- Один браузерный профиль с восемью одинаковыми окнами — не обеспечивает
  независимость сохранённых данных.

## Consequences

- Нельзя возвращать guest ID обратно в общий `localStorage`.
- Reconnect должен использовать стабильный ID текущей session.
- Команда «N телефонов» означает отдельные видимые окна/профили, а не N вкладок
  с общей identity.
