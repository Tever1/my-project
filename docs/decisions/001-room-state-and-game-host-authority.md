# Room state and game-host authority

> Игровая часть этого решения уточнена и частично заменена
> [`006-server-game-snapshots-and-private-views.md`](006-server-game-snapshots-and-private-views.md).
> Сервер по-прежнему не хранит комнаты постоянно, но теперь удерживает
> канонический снимок активной игры и выдаёт персонализированные представления.

## Context

Приложению нужны общая комната, TV и несколько телефонов с быстрым realtime-
обменом. MVP не использует базу данных. Изначально полный state каждой игры
на сервере не хранился; эта часть решения заменена ADR-006.

## Decision

Socket.io server авторитетен для комнаты: участники, owner/host, выбранная игра,
старт/конец и permissions. По ADR-006 он также удерживает канонический игровой
snapshot и выдаёт персонализированный state подключившемуся или вернувшемуся
клиенту. Браузер игрового хоста остаётся UI-контроллером разрешённых переходов,
но больше не является единственным источником восстановления.

Комнаты хранятся в памяти одного Node-процесса.

## Reason

Это минимальная архитектура для локальной party-game с низкой задержкой и без
инфраструктуры БД. Она уже используется всеми семью играми.

## Alternatives

- Полностью серверный reducer для каждой игры — надёжнее, но потребовал бы
  переписать все игровые страницы и протоколы.
- Persistent database/event log — полезно для восстановления, но не требовалось
  для локального MVP.

## Consequences

- Рестарт сервера уничтожает комнаты.
- Отключение или перезагрузка game host не удаляет его из активной игры;
  reconnect получает full-state snapshot с сервера и не полагается только на
  live-events.
- Горизонтальное масштабирование невозможно без общего state/adapter.
- Новые действия должны проверять actor/host permissions на сервере, особенно
  если они раскрывают секреты или меняют результат.
