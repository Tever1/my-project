## Результат

- Новый тёмно-синий фон, обычная UI-типографика, компактная навигация,
  проектные image-иконки разделов/игр/доступных тем, более читаемые подписи.
- Поиск и фильтры вопросов: статус проверки, отсутствие английского перевода.
- Ручной редактор ru/en текста, четырёх ответов и правильного ответа.
- Сохранение черновика, ручного решения, комментария, источника и даты.
- Изменение текста/ответов отменяет прежнее подтверждение: «Исправлен · нужна проверка».
- Новый защищённый quiz-review API хранит файлы вне Git: ключ квиза хешируется,
  запись атомарная, параллельные изменения защищены lock + revision conflict.
- Новые отчёты хранят questionIds; история доступна у отдельного вопроса.
  Старые отчёты без ID остаются в общей истории квиза, не приписываются вопросу.
- История использует native dialog для focus trap / Escape; ссылки источников кликабельны.

Навык ckm:ui-styling применён к визуальной иерархии, focus states и адаптации.

## Незавершённый scope / риски

1. Черновики НЕ используются production-игрой, что явно написано в UI.
   Production берёт статические банки из src/lib/quiz; существующие admin
   quiz-overrides также не подключены к этому выбору. Нельзя считать интерфейс
   опубликованным или обещать, что игровой вопрос изменился.
2. Нужен отдельный этап подключения опубликованных версий к новому игровому
   старту, без изменения очереди активного матча / reconnect.
3. Автоматический verdict по каждому вопросу пока не извлекается из текстового
   отчёта. Ручное подтверждение владельца отдельно от результата Codex.
4. Unit tests не проверяют файловый API, авторизацию или живое сохранение.
5. Если процесс аварийно остановлен во время записи, .lock может остаться;
   понадобится проверка/очистка точного lock перед повторным сохранением.
6. Требуются свежий review и разрешённая визуальная проверка. Exact-viewport
   preflight не выполнен, поскольку browser QA не разрешён этой командой.
