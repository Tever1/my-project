# TASK-522 — локальная генерация через Codex

## Результат

Админские генераторы перенесены с OpenRouter на установленный Codex CLI
с ChatGPT-входом. Это отдельные короткие сессии генерации, не отправка сообщений
в текущий системный чат. API-ключ OpenAI и внешние провайдеры не используются.
Выбран one-shot `codex exec`, а не постоянный app-server: задачи независимы,
история диалога им не нужна. Новая SDK-зависимость не добавлена.

## Изменения

- `src/lib/admin-codex.ts`: локальный запуск, ключ доступа, Origin/body checks,
  один запрос за раз, таймауты, read-only sandbox, выключенные shell/delegation,
  проверка и декодирование файла изображения.
- `src/lib/admin-fetch.ts`, `src/components/admin/CodexAdminAccess.tsx`,
  `src/app/admin/page.tsx`: ключ на вкладку и передача защищённых запросов.
- `src/app/api/admin/{generate-words,generate-locations,generate-bg-prompt,
  generate-image,fact-check,game-item,quiz-item}/route.ts`: локальный генератор,
  проверки входных/выходных данных, сохранён контракт ответов UI.
- `src/app/api/admin/run/route.ts`: старый запуск внешних скриптов отключён (410).
  Текущая админка этот маршрут не использовала. Сами CLI-скрипты не изменялись.
- `src/lib/admin-codex.test.ts`: проверки доступа, Origin, размера тела,
  корректной передачи JSON и блокировки параллельного запроса без запуска модели.
- `docs/ADMIN_CODEX.md`, PROJECT_CONTEXT, TASKS, handoff: подключение и статус.

## Ограничения / следующий шаг

Нужно отдельное свежее ревью безопасности перед публикацией и разрешённая
проверка кнопок в браузере. Ключ хранится в игнорируемой папке data, содержимое
не включать в Git/отчёты. Остальные admin API ещё не имеют полноценной защиты;
интеграция предназначена для локального Mac, не публичного сервера.
Генерация расходует лимиты Codex. Доступность модели/генератора зависит от аккаунта.

## Дополнение — поиск для проверки достоверности

по умолчанию остаются без поиска. UI и инструкция синхронизированы.
Настройка сверена через OpenAI Docs:
https://learn.chatgpt.com/docs/config-file/config-reference
TypeScript и scoped ESLint прошли. Live факт-чек и browser QA в этом дополнении
не запускались; корректность каждого вывода модели не гарантируется.

## Исправление Origin — 2026-09-13

Пользователь сообщил 403 «Недопустимый источник запроса» при факт-чеке.
Локальный regression воспроизвёл 403 для Origin/Host localhost:3000 при
NextRequest.url с внутренним 0.0.0.0:3000 (bind address custom server).
Проверка теперь использует протокол запроса и Host, не X-Forwarded-Host.
Ключ остаётся обязательным; другой origin, порт и протокол отклоняются.
Тесты localhost/IPv4/LAN/IPv6 и отрицательные сценарии: 4/4 tests passed.
TypeScript, scoped ESLint, diff-check проверены при завершении.
Применён diagnosing-bugs: воспроизведение до правки и успешный regression после.
HTTP-проверку заблокировал auto-review из-за лимита; вместо неё выполнен
изолированный тест без сети/генерации. Live/browser факт-чек ещё не проверен.
Сервер не перезапускался; commit/push не выполнялись.

## Запоминание входа — 2026-09-13

По запросу владельца добавлена подписанная 30-дневная сессия вместо ключа
в sessionStorage. Новый `/api/admin/session` проверяет вход, выдаёт cookie
HttpOnly/SameSite=Strict/Path=/api/admin, Secure при HTTPS и очищает при выходе.
Срок проверяет сервер; продление требует ключа. Cookie-запросы без Origin или
с чужим Origin отклоняются. UI проверяет сессию при открытии и показывает
«Запомнить на 30 дней» / «Выйти». admin-fetch передаёт same-origin credentials.
Привязка к браузеру/hostname, не аппаратному MAC. Инструкция обновлена.
6/6 локальных тестов прошли: подпись, срок, смена ключа, флаги cookie,
вход/статус/выход, Origin, прежние защиты. Browser QA и реальный перезапуск
браузера не выполнялись. Перед публикацией по-прежнему нужно отдельное ревью.
Выход удаляет cookie, но не отзывает украденную копию; ротация ключа отзывает все.

## История факт-чеков — 2026-09-13

Добавлена кнопка «Отчёты» выбранного квиза. Fact-check сохраняет результат,
дату, quizKey/label и текст проверенных вопросов в data/quiz-check-reports/.
Защищённый POST quiz-check-reports возвращает историю без запуска генерации.
Хранилище использует отдельный UUID-файл на результат, пути не зависят от quizKey.
Все три UI-вызова fact-check передают принадлежность квизу; ключ QuestionViewer
отделяет асинхронные ответы разных квизов при переключении. Неудачная запись
не теряет результат: пользователю выводится предупреждение с полным отчётом.
Новые файлы: quiz-check-reports.ts, его тест, API route и QuizCheckReports.tsx.
7/7 локальных тестов прошли, включая повторное чтение, изоляцию квизов и снимок
вопросов. TypeScript/scoped lint/diff-check проверены при завершении.
Browser QA и live генерация в этой итерации не выполнялись; старые исчезнувшие
отчёты до включения сохранения в истории отсутствуют. Build/commit/push не делались.
