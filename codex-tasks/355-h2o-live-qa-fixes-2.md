## 1. TV во время выбора темы хостом — нужен явный статус ожидания, а не общая заставка

`tv/.../page.tsx`, блок строка ~1216:
```tsx
{(h.phase === 'topicSelect' || h.phase === 'title' || h.phase === 'teams' || h.phase === 'rules') && (
  ...
  <div className="font-mono ...">Телеигра · Тема: {h2oTopicName}</div>
```

Сейчас во время `topicSelect` (хост ещё НЕ выбрал тему — `h.topicId` дефолтно
`'general'`) TV уже показывает `Тема: Общие вопросы`, как будто тема уже
выбрана — это вводит в заблуждение. На мобильном для не-хоста в этой же фазе
уже есть правильный паттерн: `BreathingPlaceholder` с текстом «Хост выбирает
тему...» (`hundred-to-one/page.tsx`, строка ~774).

списка `title/teams/rules`, у которых логика не меняется). Для `topicSelect`

переиспользовать `BreathingPlaceholder`-стиль или что-то на текущем
визуальном языке этого экрана — glass-плашка с иконкой), БЕЗ строки
`Тема: {...}` (тема ещё не известна) и без VS-карточек команд (они на этом
этапе ещё не важны/не заполнены). Как только `h.phase` уходит из
`topicSelect` (хост выбрал тему → `roleSelect`), показывать выбранную тему
там, где сейчас она видна (steps-экран `roleSelect`/`captainSelect`/
`teamNames`, около `.steps` — там сейчас темы не видно вообще нигде, стоит
добавить маленькую подпись с выбранной темой рядом/под шапкой в этом блоке,
одной строкой, не перегружая макет).

## 2. TV во время выбора ролей ошибочно показывает комнатного хоста как «Ведущего» игры

`tv/.../page.tsx`, строка ~1201:
```tsx
const h2oHost = h2oPlayers.find((p) => h.roles[p.id] === 'host') ?? h2oPlayers.find((p) => p.isHost);
```
Фоллбэк `?? h2oPlayers.find((p) => p.isHost)` подставляет создателя комнаты
(`isHost`, room-host — НЕ то же самое, что игровая роль `host`/«Ведущий»)
всякий раз, когда ни один игрок ещё не выбрал роль «Ведущий» — из-за этого на
экране подготовки (steps-screen, колонка с QR/host-row, строки ~1299-1301) и
на заставке (строка ~1245) кажется, будто роль ведущего уже назначена
комнатному хосту, хотя это неверно — ведущим может стать любой игрок.

**Фикс:** убери фоллбэк `?? ... isHost`. Если `h2oHost` не найден (никто ещё
не выбрал роль), везде где он используется (`nickname || '—'`) должно
корректно показываться «—»/«не выбран» вместо подмены комнатным хостом.
Проверь все 4 места использования `h2oHost` (строки ~1245, ~1299, ~1301 и
любые другие через `grep -n h2oHost`).

## 3. Игрок должен уметь отменить выбор своей команды повторным нажатием

`hundred-to-one/page.tsx`, `selectRole` (строка ~284):
```tsx
const selectRole = (role: PlayerRole) => {
  if (!effectivePlayerId) return;
  if (role === 'host' && Object.entries(s.roles).some(([id, r]) => r === 'host' && id !== effectivePlayerId)) return;
  const newRoles = { ...s.roles, [effectivePlayerId]: role };
  update({ roles: newRoles });
};
```
Сейчас повторный клик по уже выбранной своей роли просто переустанавливает
её же (никакого эффекта деселекта). **Фикс:** если `myRole === role` (юзер
кликает по карточке, которая уже выбрана им) — снять выбор: удалить
`effectivePlayerId` из `s.roles` (через деструктуризацию/`delete`, не
оставляя `undefined`-значение), и разбросать патч. После этого игрок снова
видит все карточки без подсветки своей роли и может выбрать другую/ту же
заново.

## 4. TV раунд 4 («наоборот») — поля очков по бокам от таймера меняют размер вместе с цифрами таймера

`tv/.../page.tsx`, `playing`-блок, грид `grid-cols-[1fr_auto_1fr]` (строка
~1399) — команда 1 в левой `1fr`-колонке, команда 2 в правой `1fr`-колонке,
центральная карточка банка/таймера — `auto`-колонка (строка ~1416):
```tsx
{h.curQ <= 2 ? h.roundFund[h.curQ] : `${Math.floor(h.r4Time / 60)}:${(h.r4Time % 60).toString().padStart(2, '0')}`}
```
Цифры таймера (`M:SS`) рендерятся обычным (не табличным) начертанием цифр —
разные цифры имеют разную ширину в проприетарном шрифте, поэтому ширина
`auto`-колонки в центре меняется каждую секунду, и это «толкает» соседние
`1fr`-колонки с карточками команд/очков, из-за чего они визуально меняют
размер. То же может быть с самими очками команд (`.sc`/score span), если там
тоже не табличные цифры.

**Фикс:** добавь `tabular-nums` (Tailwind-класс на моноширинные цифры) на
span с таймером (и на span с банком/очками команд рядом, для консистентности
— туда же где меняются числа: `h.roundFund[h.curQ]`, `h.t1s`, `h.t2s`).
Дополнительно — если только `tabular-nums` не уберёт дрожание полностью
(там ещё есть `:` и возможна разная ширина из-за `font-extrabold`), задай
центральной карточке банка/таймера (`col-start-2`, строка ~1416) фиксированную
минимальную ширину (`min-w-[...]`), подобранную так, чтобы вмещать самое
длинное значение таймера (`0:00`..`9:59` — все 4 символа, должно быть
стабильно с `tabular-nums`) без изменения размера при смене раунда/фазы.
Проверь, что команды-карточки (1fr-колонки) после фикса больше не меняют
ширину при тиках таймера.

## 5. TV/mobile раунд 4 — очки каждой команде начислять максимум один раз за раунд, дальше без модалки выбора команды

`hundred-to-one/page.tsx`, `openAns` (строка ~425), ветка `else` для раунда 4
(строка ~468 и далее):
```tsx
} else {
  // Round 4 (наоборот) — show assign modal
  newQState[s.curQ][idx].rev = true;
  newQState[s.curQ][idx].pub = true;
  setS(prev => ({ ...prev, qState: newQState }));
  broadcast({ qState: newQState });
  setAssignModal({ idx, pts });
}
```
Сейчас модалка «Какой команде записать очки?» (`assignModal`, JSX ~строка
1344, кнопки вызывают `assignPts(1)`/`assignPts(2)`/`assignPts(0)` —
строка ~499) появляется при КАЖДОМ открытии ответа в раунде 4, сколько бы
раз это ни происходило. Нужно: **каждой из двух команд очки в раунде 4
можно начислить не более одного раза за весь раунд.**

**Фикс:**
- В `openAns` перед вызовом `setAssignModal(...)` вычисли, каким командам
  очки в этом раунде уже начислялись — по `s.qState[s.curQ]`, где поле
  `.to` уже хранит, какой команде ушли очки за конкретный ответ (`to === 1`
  → команде 1, `to === 2` → команде 2, `to === 0`/не тронуто → ещё никому).
  Значит: `team1Credited = s.qState[s.curQ].some(a => a.to === 1)`,
  `team2Credited = s.qState[s.curQ].some(a => a.to === 2)`.
- Если ОБЕ уже `true` — не показывать модалку вообще: просто открой ответ
  как обычный reveal (уже делает верхняя часть блока — `rev`/`pub` в true),
  без `setAssignModal`.
- Если хотя бы одна команда ещё НЕ получала очки — показывай модалку как
  раньше, но в `assignPts`/в самой модалке задизейбль/скрой кнопку той
  команды, которая уже получила очки в этом раунде (передай
  `team1Credited`/`team2Credited` в стейт модалки или прочитай их заново в
  месте рендера модалки из `s.qState[s.curQ]`).
- Клик «Никому» (`assignPts(0)`) НЕ должен считаться начислением — не
  занимает слот команды, доступен всегда пока модалка вообще показывается.
- Сброс раунда (`resetRound`/переход в новый раунд) должен, как и раньше,
  очищать `qState[3]`, так что счётчик начислений сам обнулится при новом
  прогоне раунда 4 (если раунд 4 может повториться в текущем флоу — проверь
  по коду `r4Reset`/`resetRound`, ничего дополнительно менять не нужно, если
  `qState` там и так пересоздаётся).

## 6. «Сыграть ещё раз» должен открывать выбор темы, а не сразу начинать раунд

**Важно:** это меняет решение из TASK-354 п.11. Тогда я просила расследовать
баг «уходит не туда» предполагая, что верно — `phase: 'buzzer'`. Пользователь
явно подтвердил: **правильное поведение — открыть меню выбора темы**
(полный рестарт), а не пропускать сразу к баззеру со старыми ролями/командами.

Сейчас (`hundred-to-one/page.tsx`, строка ~1607) кнопка «Сыграть ещё раз» (в
фазе `final`) вызывает ТУ ЖЕ функцию `startGame` (строка ~375), что и кнопка
«НАЧАТЬ ИГРУ» в фазе `title` (строка ~994) — `startGame` уходит в
`phase: 'buzzer'`, сохраняя `topicId`/`roles`/`captains`/`t1n`/`t2n`. Это
верно для перехода `title → buzzer` (первый старт после уже пройденной
настройки), но НЕ подходит для «Сыграть ещё раз» — там нужен полный рестарт.

**Фикс:** заведи отдельную функцию (например `playAgain`), которая делает
полный сброс через `mkInitial()` (`phase: 'topicSelect'`, дефолтные
`topicId`, пустые `roles`/`captains`/`teamNameConfirmed`/`t1n`/`t2n`/очки и
т.д. — как при самом первом входе в игру), с сохранением только `players`
(список игроков комнаты, чтобы никого не выкинуть) — используй
`sRef.current` так же аккуратно с синхронным обновлением `sRef.current`, как
уже сделано в `startGame` (по образцу фикса из TASK-354 п.11, чтобы не
словить тот же race). Привяжи кнопку «Сыграть ещё раз» (строка ~1607) к
`playAgain` вместо `startGame`. `startGame` саму не трогай — она по-прежнему
нужна для перехода `title → buzzer`.
