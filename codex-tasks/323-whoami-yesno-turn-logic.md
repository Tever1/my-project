# TASK-323: «Кто я?» — новая механика передачи хода через «Да»/«Нет»

## Контекст

Игра «Кто я?» (`who-am-i`). Игрок вслух задаёт вопрос с ответом да/нет,
остальные отвечают голосом. Раньше передача хода была ПОЛНОСТЬЮ ручной:
единственная кнопка «Дальше» одновременно засчитывала вопрос и сразу
передавала ход следующему игроку.

Новое правило (согласовано с продактом, зафиксировано в
`docs/who-am-i-design-brief.md`, раздел 1 «Обновлённая механика передачи
хода»):

- Кнопка «Дальше» заменяется на ДВЕ кнопки: **«Да»** и **«Нет»**.
- Ответ **«Нет»** → вопрос засчитан, ход СРАЗУ переходит к следующему
  игроку (эквивалент прежней «Дальше»).
- Ответ **«Да»** → вопрос засчитан, ход ОСТАЁТСЯ у текущего игрока
  (он задаёт следующий вопрос).
- **Лимит: максимум 3 «Да» подряд.** На 3-м «Да» ход принудительно
  передаётся следующему игроку (как если бы был «Нет»), несмотря на то
  что ответ был «Да». Счётчик серии «Да» сбрасывается в 0 при любой
  передаче хода (по «Нет», по лимиту, или когда текущий игрок угадывает
  персонажа и выбывает из очереди ходов).

Это ТОЛЬКО логика. Визуальный редизайн экранов (как выглядят кнопки,
индикатор серии) — отдельная задача после того, как вернутся макеты от
«Claude Design», НЕ делать сейчас. Не трогай стили/классы кнопок сверх
необходимого для замены одной кнопки на две — сохраняй текущий визуальный
язык (`GlassButton`), без редизайна.

## Что нужно сделать

### 1. Клиент (мобильный экран)

Файл: `src/app/game/[roomId]/who-am-i/page.tsx`

- Убрать кнопку «Дальше» (строки ~510-520, `{l('Дальше', 'Next')}`).
- Добавить на её место две кнопки: «Нет» / «Да» (`l('Нет','No')` /
  `l('Да','Yes')`), `variant="default"`, тот же `flex-1` layout что был у
  «Дальше», рядом с существующей «Я знаю!» (`variant="primary"`, не
  трогать).
- Клик «Нет» → тот же эффект, что раньше был у «Дальше»:
  `handleQuestionAsked()` + `handleNextTurn()` (эти функции уже есть,
  логика не меняется).
- Клик «Да» → новый обработчик: засчитать вопрос
  (`handleQuestionAsked()`), но НЕ звать `handleNextTurn()`. Вместо этого
  инкрементировать локальный счётчик серии «Да» для текущего игрока. Если
  счётчик достиг 3 — вызвать `handleNextTurn()` (как «Нет») и сбросить
  счётчик в 0.
- Счётчик серии «Да» — новое поле в game state, синхронизируется по
  сокету так же, как остальные поля (`questionsAsked`, `guessedPlayers` и
  т.п.) — все клиенты (включая TV) должны видеть актуальное значение, а
  не только хост. Посмотри как уже транслируется `sync-state`/`ask-question`
  action (`case 'ask-question'` в `useEffect` на `on(...)`, около строки 183)
  — новое поле должно обновляться тем же паттерном (host рассылает action,
  все клиенты применяют его к локальному `gs`).
- Сброс счётчика серии «Да» в 0 при:
  - передаче хода на «Нет» или на лимите 3,
  - успешном угадывании текущим игроком (случай `case 'guess'`, если
    `payload.correct`, currentTurnIndex тоже увеличивается — счётчик надо
    сбросить туда же).
- Индикатор серии «Да» на экране (1/2/3 точки или текст) — минимальный
  вариант сейчас (`«Да» подряд: {N}/3` текстом рядом с кнопками), без
  дизайна — финальный вид переделает следующая задача после макетов.

### 2. Проверить TV-файл на затрагиваемость

Файл: `src/app/tv/[roomId]/[gameType]/page.tsx` — у who-am-i сейчас нет
кастомного TV-блока (генерик-фоллбэк, см. дизайн-бриф раздел 2.2). Просто

что-то показывать на TV для этого поля — TV-редизайн будет отдельной
задачей после макетов).

## Acceptance

- `npm run lint` и `tsc` без новых ошибок.
- Кнопки «Да»/«Нет» видны текущему игроку вместо «Дальше».

- Угадывание персонажа сбрасывает счётчик серии «Да» (не переносится на
  следующего игрока).
- Classic-механика (список персонажей, очки, `calculateScore`,
  порядок ходов `turnOrder`) не изменена.
