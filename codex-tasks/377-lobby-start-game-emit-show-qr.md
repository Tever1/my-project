# TASK-377: `handleStartGame` не сообщает серверу о показе QR — рассинхрон с телефоном

## Контекст

Живой QA после TASK-376 выявил баг: хост нажимает «НАЧАТЬ ИГРУ» на TV
(`handleStartGame`, `src/components/lobby/Lobby.tsx` ~строка 669-681) — TV
локально переключается на экран ожидания игроков с QR-кодом
(`setIsWaitingForPlayers(true)`), но **не эмитит `room:show-qr`**. Серверный
`room.showQrCode` (добавлен в TASK-376) остаётся `false`. В результате
телефон, который теперь инициализирует кнопку из персистентного серверного
состояния, показывает «+ Добавить игрока» вместо «Вернуться в лобби», хотя
QR на TV реально уже показан — рассинхрон.

Также при реальном старте игры (`handleEmitStartGame`, эмитит `game:start`,
~строка 724-727) серверный флаг не сбрасывается в `false` — если он был
`true`, это может привести к тому, что телефон, открывший `/join/[code]`
уже ПОСЛЕ старта игры, увидит «Вернуться в лобби», хотя экран ожидания с QR
давно закрыт (TV уже ушёл на другой роут).

## Что сделать

В `src/components/lobby/Lobby.tsx`:

1. В `handleStartGame` (~строка 669-681) — сразу после
   `setIsWaitingForPlayers(true)` добавить:
   ```tsx
   emit('room:show-qr', { code, show: true });
   ```
   (использовать ту же переменную `code`, что уже используется в функции для
   `emit('game:select', ...)`).

2. В `handleEmitStartGame` (~строка 724-727) — перед или сразу после
   `emit('game:start', { code: roomCode })` добавить:
   ```tsx
   emit('room:show-qr', { code: roomCode, show: false });
   ```
   чтобы серверный флаг сбрасывался в момент реального старта игры.

Никакой другой логики не трогать. Whitelist — только этот файл.
