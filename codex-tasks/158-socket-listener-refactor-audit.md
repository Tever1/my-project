# TASK-158 — Аудит socket-listener'ов: кандидаты на вынос в хуки

## Контекст

В TASK-156/157 мы вынесли подписку `game:ended` в `useNavigateOnGameEnd`.
До этого её код был размазан по 8 файлам. Подозреваю, что в проекте есть
ещё похожие паттерны — повторяющиеся `on('xxx', ...)` подписки в
игровых страницах и в `Lobby.tsx`, которые можно вынести в один общий
хук или helper.

**Эта задача — только аудит, никаких правок production-кода.** Codex
читает файлы, грепает, и пишет структурированный отчёт с кандидатами,
приоритетом и оценкой риска. По отчёту мы потом отдельными тасками
сделаем рефакторинг.

**НЕ ТРОГАТЬ ВООБЩЕ:** ничего в `src/`, `server.mts`, конфигах. Это

## Что искать

### A. Повторяющиеся `on('xxx', ...)` подписки в клиенте

Грепни `on(` и `useSocket()` по client-файлам. Для каждой найденной
подписки заполни строку в таблице ниже.

Особое внимание:
1. **`game:action`** — наверняка в каждой игре, но содержимое handler'а
   разное. Скорее НЕ кандидат (логика игроспецифична). Зафиксируй это
   явно, чтобы было понятно почему пропустили.
2. **`*:request-state`** паттерн — quiz/crocodile/alias/100to1, TV
   запрашивает state у хоста. Кандидат на хук
   `useRequestStateOnMount(gameType)`?
3. **`*:sync`** — host re-broadcasts state. Симметричный к request-state.
4. **`room:show-qr`** (TASK-154) — клиентский listener только в Lobby?
   Или ещё где-то?
5. **`player:away` / `player:back`** — Page Visibility wiring. Уже один
   раз использовано — кандидат на хук `usePresence()`.
6. **`room:state`** — где-то ещё кроме Lobby?

### B. Повторяющиеся `emit('xxx', ...)` паттерны

- `emit('room:get-state', ...)` — каждая игровая страница в `useEffect`
  делает это. Возможно вынести в общий хук `useGameRoomState(roomId)`?
- `emit('game:action', ...)` — везде с одинаковой shape `{ code, action, payload }`.
  Helper `useGameBroadcast(roomId, action)` мог бы упростить.

### C. Component-side cleanup patterns

Есть ли `useEffect` с тремя+ unsubscribe'ами, где можно было бы
использовать комбинатор?

### D. Page Visibility / Reconnect logic

В CLAUDE.md описано как `useSocket().onConnect` плюс
`document.hidden` → `player:away/back`. Это растянуто на Lobby +
`use-socket.ts`. Не ясно из аудита кода — но проверь, нет ли
дубликата в других страницах.
