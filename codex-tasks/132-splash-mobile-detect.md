## Цель

При первом заходе на `/` пользователь видит splash-экран с двумя кнопками:
**«Играть»** (десктоп) и **«Играть на телефоне»** (мобильный). Выбор
сохраняется в `localStorage` и больше не показывается. После выбора рендерится
текущий `<Lobby />` как раньше — мобильная ветка будет подключена в TASK-135.

---

## Контекст

Большой архитектурный пивот: десктоп = TV/лобби, телефон = пульт.
Splash — точка входа. Auto-detect (`useIsMobile`) только **подсвечивает**
рекомендуемую кнопку, но не выбирает за пользователя — он должен явно нажать.
Это нужно чтобы человек на ноутбуке с узким окном (планшет / split-screen)
мог осознанно выбрать desktop-режим, а не получить мобильный по ошибке.

Сейчас `src/app/page.tsx` сразу рендерит `<Lobby />`. Добавляем layer выбора
поверх.

## Шаги реализации

1. **Хук `usePlayMode()`** в `src/lib/use-play-mode.ts`:
   - Ключ в localStorage: `party-hub-play-mode` (значения: `"desktop"` | `"mobile"`).
   - SSR-safe (читать только в `useEffect`, начальное значение `null`).
   - Экспортирует: `mode`, `setMode(m)`, `reset()` (удаляет ключ).
   - Слушает `storage` event чтобы синхронизироваться между вкладками.

2. **`Splash.tsx`** — fullscreen-экран, стиль в духе текущего лобби
   (тёмный фон, GlassPanel из `src/components/glass`, кнопки `GlassButton` из
   `src/components/ui`).
   - Заголовок: «Party Games Hub» (или h1 с тем же шрифтом, что в TopBar лобби).
   - Подзаголовок: «Где вы играете?»
   - Две большие кнопки (вертикально на мобильном, горизонтально на десктопе):
     - **«Играть»** с подписью маленьким шрифтом «на этом экране / десктоп»
     - **«Играть на телефоне»** с подписью «джойн в комнату по QR»
   - Если `useIsMobile()` (импортировать из существующего хука, **не дублировать**
     — он сейчас живёт внутри `Lobby.tsx`; выдели его в отдельный файл
     `src/lib/use-is-mobile.ts` и реэкспортируй из Lobby для обратной совместимости),
     рекомендуемая кнопка получает per-game accent ring (используй цвет
     `--color-game-quiz` `#facc15` как нейтральный акцент) и подпись
     «(рекомендуется для вашего устройства)».
   - onClick → `setMode('desktop' | 'mobile')`. Никакой навигации не делать —
     гейт сам перерендерится.
   - Только русский (это внутренняя точка входа, i18n не нужен).

3. **`ModeGate.tsx`** — обёртка:
   ```tsx
   const { mode } = usePlayMode();
   if (mode === null) return <Splash />;
   return <>{children}</>;
   ```
   - Пока mode читается из localStorage (первый рендер), показывать
     `null` (не мигать splash'ем для пользователей с уже сохранённым выбором).
     Подойдёт паттерн: `const [hydrated, setHydrated] = useState(false)`,
     `useEffect(() => setHydrated(true), [])`, рендерить null до hydrated.

4. **`src/app/page.tsx`** — обернуть `<Lobby />` в `<ModeGate>`:
   ```tsx
   <Suspense fallback={null}>
     <ModeGate>
       <Lobby />
     </ModeGate>
   </Suspense>
   ```
   **Важно:** ModeGate **только на `/`**. На `/lobby/[roomId]` гость по QR
   должен попадать сразу в комнату — splash там не нужен. Файл
   `src/app/lobby/[roomId]/page.tsx` не трогать.

5. **Dev reset.** Добавить query-param `?reset-mode=1` на `/`: если параметр
   присутствует, ModeGate вызывает `reset()` в useEffect и убирает параметр
   через `router.replace('/')`. Это для разработки — никакой UI-кнопки не надо.

6. Прогнать `npm run lint` и `npm run build`.

> Если по ходу выясняется что нужен дополнительный шаг или другой файл —
> остановиться, описать в отчёте, вернуть управление Claude.

## Ограничения и подводные камни

- **SSR:** Next.js может префетчить страницу. Все обращения к `localStorage`
  и `window` — только в `useEffect` / event handlers. Иначе hydration mismatch.
- **Никакого мерцания:** если пользователь уже выбрал режим, он не должен
  видеть splash даже на 100мс. Pattern с `hydrated` флагом — обязателен.
- **`useIsMobile` дубликат.** Текущая реализация живёт прямо в `Lobby.tsx:141`.
  Вынести в `src/lib/use-is-mobile.ts`, в Lobby поменять импорт на
  `import { useIsMobile } from "@/lib/use-is-mobile"`. Это единственное
  допустимое касание `Lobby.tsx` — только импорт, тело хука удалить.
  Если этот рефакторинг кажется выходом за whitelist — оставь дубликат хука
  локально в Splash.tsx и опиши это в отчёте.
- **i18n не нужен** (внутренняя точка входа, по аналогии с `/design-tokens`).
- **Комментарии в коде** — английский.
- **Не использовать `next/dynamic`** для отключения SSR — паттерн с `hydrated`
  достаточен и не ломает streaming.

## Открытые вопросы для Codex

- Анимация появления splash → нужна? — **минимальная: fade-in 200ms, не более.
  Никаких сложных motion-композиций**. Достаточно `motion.div` с `initial={{opacity:0}} animate={{opacity:1}}`.
- Логотип / иконка над заголовком? — **нет**, только текст (визуал доработаем позже).
- Запоминать выбор в cookie дополнительно? — **нет, только localStorage**.
