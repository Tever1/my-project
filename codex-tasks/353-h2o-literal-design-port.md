# TASK-353: «100 к 1» — буквальный порт дизайна из 13 новых design-ref файлов

## Контекст и почему этот таск существует

Пользователь положил 13 новых HTML-макетов в `public/design-ref/100 к 1 - *.html`
(7 мобильных + 6 TV). Это финальный дизайн игры «100 к 1», сделанный тем же
инструментом/языком, что и уже перенесённый ранее дизайн «Кто я?»
(см. `codex-tasks/332-whoami-literal-design-port-and-separate-guess-screens.md`
как образец подхода — прочитай его для стиля, но не копируй телом задачи).

Текущий код игры (`src/app/game/[roomId]/hundred-to-one/page.tsx` и блок
`gameType === 'hundred-to-one'` в `src/app/tv/[roomId]/[gameType]/page.tsx`)
визуально — старый: голые Tailwind-классы, эмодзи вместо иконок
(💯🎙️🟡🔴⏳), нет фирменной атмосферы (`h2o-bg` с лучами/свечением),
нет карточек-стекла в стиле макета. **Нужно перенести дизайн буквально**
(1 в 1 — цвета, радиусы, отступы, тени, размеры шрифтов, структура), а не
«вдохновиться». Игровую логику, socket-события и структуру state — НЕ ТРОГАТЬ,
это чисто визуальная работа.

## Обязательное чтение ПЕРЕД началом

### 1. Все 13 файлов в `public/design-ref/100 к 1 - *.html` — читать ПОЛНОСТЬЮ

Эти файлы ссылаются на несуществующие в репозитории `foundation/tokens.css`,
`mobile/phone.css`, `tv/tv.css`, `h2o/h2o.css` — поэтому при открытии в
браузере они выглядят голыми (без стилей). **Это ожидаемо и не баг** — каждый
файл переопределяет всё нужное для СВОЕГО экрана в собственном инлайн
`<style>` в `<head>`, этого достаточно как источник истины. Общие/отсутствующие
классы (`.glass`, `.glass-strong`, `.btn`, `.h2o-accent-card`, `.h2o-pulse`,
`.tm-dot`, `tm1-card`/`tm2-card`, `.avatar` и т.п.) — смотри пункт 3 ниже, они
уже есть в проекте под другими именами.

**Игнорировать во всех файлах:**
- `.phone-stage`/`.phone`/`.island`/`.status`/`.home-ind` — имитация корпуса
  телефона для показа макета, в реальном коде их нет (страница открывается в
  настоящем браузере/вебвью).
- `.tv-stage`/`.tv-screen` внешняя обёртка с `fit()`-скриптом (scale-to-fit
  1920×1080) — тоже только для показа макета.
- `.appbar` (шапка с иконкой игры + кодом комнаты) на мобильном — в реальном
  коде это уже рендерит `GameLayout`, отдельно реализовывать не нужно.
- `.tv-brand` (иконка+название в левом верхнем углу TV) — сверь, возможно уже
  есть эквивалент в TV-шапке для других игр, переиспользуй тот же паттерн.
- Скрипты `fit()` в конце каждого файла — не переносить, это утилита демо-стенда.

Всё что внутри `.content` (мобильный) или `.screen` (TV) после шапки —
это и есть реальный контент экрана, переносить нужно именно это.

### 4. Цвета команд — семантические, НЕ трогать

`#ffe155` (жёлтый, команда 1 / `t1n`) и `#ff7a70` (красный, команда 2 / `t2n`),
классы `tm-dot t1`/`t2`, `tm1-card`/`tm2-card` — это **семантические цвета
команд**, они остаются как в макете и НЕ заменяются янтарным акцентом игры
(в отличие от «Кто я?», где акцент был единым голубым для всей игры). Янтарный
акцент (`--h2o-1`/`--color-game-h2o`) используется только для нейтральных/нейтрально-нейтрального
контента: банк, ведущий, таймер, множитель раунда, общий бренд-иконка игры.

### 5. SVG-иконки — брать инлайн из макетов буквально

Каждый файл уже содержит нужные inline SVG (`<svg viewBox="0 0 24 24" ...>`)
для своих иконок (микрофон ведущего, кубок победы, вопрос, буззер-таймер,
QR-код и т.д.) — копируй их 1 в 1 как React SVG-элементы (или вынеси в общий

условные Lucide-иконки — только эти конкретные path'ы из макета.
