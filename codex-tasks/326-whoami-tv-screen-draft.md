# TASK-326: «Кто я?» — черновой TV-рендер («игровое поле»), ДО финального редизайна

## Контекст

Продакт хочет посмотреть ПРИМЕРНО как будет выглядеть «игровое поле»
(TV-экран) для игры «Кто я?», не дожидаясь финального визуала от
«Claude Design» (ТЗ уже отправлено дизайнеру отдельно,
`docs/who-am-i-design-brief.md`). Это ЧЕРНОВАЯ реализация для быстрого
превью — функционально рабочая, но НЕ нужно вылизывать анимации/тайминги
до пикселя, так как через какое-то время сюда прилетит финальный визуал
поверх этой структуры. Приоритет — рабочая структура по фазам и данные,
а не полировка.

Сейчас у `who-am-i` на TV-экране НЕТ кастомного рендера — падает в
GENERIC-фоллбэк в конце файла `src/app/tv/[roomId]/[gameType]/page.tsx`
(строка ~2066, просто шапка + список игроков + текст «Игра идёт —
смотрите на телефонах!»). Задача — добавить блок
`if (gameType === 'who-am-i') { ... }` ПЕРЕД GENERIC-рендером, по
образцу уже существующих блоков (`if (gameType === 'mafia')` в этом же
файле, строка ~1988 — лучший референс структуры: свой `useState` для
зеркального состояния игры + ветка в общем `game:action`-листенере +
JSX-рендер с `GameSurface`).

## Как устроена синхронизация состояния (важно понять перед началом)

Мобильная страница `src/app/game/[roomId]/who-am-i/page.tsx` шлёт все
действия через `useGameBroadcast(roomId, 'who-am-i')`, что на сервере
превращается в событие `game:action` с `{ action: 'who-am-i', payload }`,
где `payload` — это `GameAction` из мобильного файла:
`{ type: 'start-game' | 'sync-state' | 'next-turn' | 'ask-question' | 'guess' | 'end-game', ... }`.

TV уже слушает `game:action` в одном общем `useEffect` (искать
`const unsub2 = on('game:action', ...)`, там уже есть ветки
`if (action === 'quiz') {...}`, `if (action === 'mafia') {...}` и т.д.
— добавь туда же `if (action === 'who-am-i') {...}` с `switch` по
`payload.type`, зеркально обновляющий локальный `whoAmIState` (по
аналогии с `setMafiaState` чуть выше в этом же файле).

**Не добавляй request-state / новый socket-эвент** — у Мафии на TV
такого тоже нет (известное ограничение, не в этом ТЗ), достаточно что
TV корректно накапливает состояние с момента когда сам подключился и
слушает `game:action`. Если TV подключается уже посреди игры без
request-state — ничего страшного для черновой версии, актуальное
состояние появится с ближайшим действием игрока.

## Что рендерить — 3 фазы (по данным `whoAmIState.phase`)

Используй ТОЛЬКО существующие emoji-иконки (как сейчас в мобильном
файле — 🤔 🏆 🎉 ❌ ✅ ⭐ 🥇🥈🥉), НЕ используй кастомный SVG icon-сет
из `/design-tokens` (`WhoAmIIcon` или подобное) — его встраивание в код
игры это отдельная задача уже ПОСЛЕ финального редизайна.

### `lobby`

- По центру: крупная иконка 🤔 + заголовок «Кто я?» / «Who Am I?» +
  подзаголовок-подсказка одной строкой («Угадай, кем тебя назначили —
  задавай вопросы Да/Нет» / аналог на en).
- `{qrOverlay}` в конце (как во всех остальных TV-блоках — просто
  вставить компонент, уже готов).
- Ряд карточек подключённых игроков (никнейм + корона у хоста) — тот
  же паттерн, что в GENERIC-рендере (`players.map(...)`, глянь строки
  ~2094-2101 для копипаста стиля).

### `playing`

Верхний HUD (`bg-black/20 backdrop-blur-sm border-b`, как у Mafia-блока):
- Слева — иконка 🤔 + название игры.
- По центру — «Сейчас ходит: {имя текущего игрока}» крупно.
- Справа — «Угадали: {guessedPlayers.length} из {turnOrder.length}».

Определи текущего игрока так же, как в мобильном файле: активный порядок
= `turnOrder.filter(id => !guessedPlayers.includes(id))`, текущий =
`activeOrder[currentTurnIndex % activeOrder.length]` (см. случай
`ask-question` в мобильном reducer для образца этой формулы).

Центр экрана — одна крупная hero-карточка активного игрока:
- Никнейм крупно (ищи никнейм в `players` по id).
- Персонаж **замаскирован** — просто плейсхолдер-блок с текстом «???»
  (или иконкой 🤔), пока НЕ выполнено одно из: игрок угадал (тогда он
  вообще уже не активный — до этого не дойдёт), либо ход завершился
  (после завершения хода это уже не текущий игрок — рендерится в
  мини-ряду ниже, там персонаж и так не показываем, см. ниже). Так что
  на практике: персонаж активного игрока на hero-карточке ВСЕГДА
  скрыт, просто явно закомментируй эту логику для ясности.
- Счётчик «Вопросов задано: {questionsAsked[currentPlayerId] ?? 0}» под
  именем.

Под hero-карточкой — компактный горизонтальный ряд остальных игроков
(`turnOrder` минус текущий), мини-пилюли: никнейм + маленькая зелёная
галочка ✅, если игрок в `guessedPlayers`, иначе без иконки. Персонаж в
мини-ряду НЕ показываем.

Реакция на попытку угадать — простой overlay на пару секунд при
получении `payload.type === 'guess'`:
- Правильно (`payload.correct === true`) → крупно 🎉 + имя игрока +
  сам угаданный текст (`payload.guess`).
- Неправильно → крупно ❌ + текст попытки.
Реализуй как локальный state (например `lastGuessResult`) с
`window.setTimeout` на самоочистку через ~3 секунды — не нужен сложный
AnimatePresence, простой conditional render с `motion.div` и `key`
достаточно для черновика.

### `finished`

- Заголовок «Игра окончена!» / «Game over!».
- Список результатов, отсортированный по `scores` по убыванию: место,
  никнейм, персонаж (или «не угадал», если `guessedPlayers` не включает
  игрока), очки. **Для черновика — БЕЗ сложной последовательной
  анимации reveal** (это чисто визуальная фишка финального редизайна,
  сейчас просто отрендери готовый список сразу, можно с обычным fade-in
  всего блока). Топ-3 подсвети медалями 🥇🥈🥉 перед именем.
