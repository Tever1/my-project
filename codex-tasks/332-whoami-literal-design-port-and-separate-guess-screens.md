# TASK-332: «Кто я?» — буквальный порт дизайна из design-ref + отдельные экраны ввода/оспаривания/судьи

## Контекст и почему этот таск существует

TASK-331 уже сделал первый визуальный редизайн (голубой акцент, иконки,
анимации) — он ЧАСТИЧНО провалился ревью продакта по трём причинам:

1. **Дизайн не совпадает с референсом.** В TASK-331 я (Claude) написала
   инструкцию использовать 13 HTML-макетов из `public/design-ref/` только
   как «ориентир поверх токен-системы проекта» — это было ошибкой. Продакт
   явно сказал: нужен **буквально такой же дизайн**, как в этих файлах —
   не вдохновение, не переосмысление, а точный порт значений (цвета,
   радиусы, отступы, тени, размеры шрифтов, анимации).

2. **Оспаривание/судья/ввод ответа сделаны неправильной структурой.**
   TASK-331 встроил их как маленькие `GlassCard` внутри общего экрана
   `playing`, поверх списка игроков. В референс-файлах
   (`Кто я - Phone - Ввод ответа.html`, `...Оспаривание.html`,
   `...Судья.html`) это **три отдельных полноэкранных состояния** — весь
   контент под шапкой (`appbar`) полностью заменяется одним центральным
   блоком, список игроков и тост НЕ видны вообще. Нужно сделать так же.

3. Несколько мелких структурных расхождений (см. список ниже).

**Игровую логику, socket-события, структуру state — НЕ ТРОГАТЬ.** Это
чисто визуальная доводка. Баг счётчика «Да» (описан в известных
проблемах ниже) в этом таске НЕ чинить — отложен на отдельный таск.

## Обязательное чтение ПЕРЕД началом

### 1. Все 13 файлов в `public/design-ref/Кто я - *.html` — читать ПОЛНОСТЬЮ

Это теперь **источник истины для визуальных значений**, не «ориентир».
Каждый файл содержит инлайн `<style>` с конкретными значениями (hex-цвета,
`border-radius`, `padding`, `gap`, `font-size`, `box-shadow`,
`animation`/`@keyframes`, `transition`) для СВОЕГО экрана — переноси их
буквально (как Tailwind arbitrary values `[...]` или через `style={}`,
где так проще), не приблизительно.

**Важно про структуру макета vs реальный код:**
- Обёртка `.phone-stage`/`.phone`/`.island`/`.status`/`.home-ind` — это
  ТОЛЬКО имитация корпуса телефона для демонстрации макета, в реальном
  коде её НЕТ и не нужно (у нас уже есть `GameLayout`/`GameSurface`,
  реальная страница в браузере, не картинка телефона). Игнорируй.
- Всё что внутри `.content` (после `.appbar`) — это и есть реальный
  контент экрана, переносить нужно именно это.
- `.appbar` (шапка с иконкой игры + кодом комнаты) — в реальном коде уже
  есть свой аналог в `GameLayout`, отдельно реализовывать не нужно.
- Классы вроде `.glass`, `.glass-strong`, `.btn.wai`, `.wai-bg` определены
  в ОТСУТСТВУЮЩИХ общих файлах (`foundation/tokens.css`,
  `mobile/phone.css`/`tv/tv.css`, `whoami/whoami.css` — их физически нет
  в репозитории). Но КАЖДЫЙ файл переопределяет нужные для своего экрана
  величины в собственном `<style>` — используй их. Где значения совсем не
  видны (например базовый `.glass` фон/blur, которого нет в конкретном
  файле) — бери за основу текущие `glass-card`/`GlassCard`-стили проекта
  (`src/app/globals.css`), они уже близки к iOS-26 liquid glass эстетике
  макета.

Список файлов и что каждый показывает (мобильные — 6, TV — 7):
- `Кто я - Phone - Лобби.html`

- `Кто я - Phone - Судья.html` — **отдельный полноэкранный** экран судьи
- `Кто я - Phone - Финал.html` — обрати внимание: построчная стаггер-анимация
  появления карточек результата снизу вверх ЕСТЬ и на мобильном тоже
  (`.row-r.p6` … `.row-r.p1` разные `animation-delay`, места 6→1), не только на TV
- `Кто я - TV - Лобби.html`
- `Кто я - TV - Ход игрока.html` и `...· 10 игроков.html` — layout hero+мини-ряд,

## Конкретный список того, что нужно исправить

### A. Мобильный экран — отдельные полноэкранные состояния (главное исправление)

Сейчас (TASK-331) флоу «Я знаю!» → ввод → оспаривание → судья реализован
как набор `GlassCard`, которые появляются ДОПОЛНИТЕЛЬНО к списку игроков
внутри `renderPlaying()`. **Переделать на отдельные полноэкранные
рендер-функции**, аналогично `renderLobby()`/`renderPlaying()`/`renderFinished()`:

- Когда `showGuessInput === true` → показывать ТОЛЬКО экран ввода ответа
  (по `Ввод ответа.html`: иконка-бейдж игры + "попытка угадать" + "Так кто
  же ты?" + поле ввода с мигающим курсором + примечание про оспаривание +
  кнопки «Угадать!»/«Отмена»), список игроков и toast НЕ рендерить.
- Когда у текущего игрока `isMyPendingGuess && gs.guessNeedsConfirm` →
  показывать ТОЛЬКО экран оспаривания (по `Оспаривание.html`: янтарная
  карточка на всю доступную высоту — иконка, "не совпало автоматически",
  заголовок "Настаиваешь, что это верно?", подпись, блок "твой ответ" со
  значением, поясняющий текст про случайного судьи, кнопка «Подтвердить»).
- Когда `isGuessJudge && gs.guessAwaitingJudge` → показывать ТОЛЬКО экран
  судьи (по `Судья.html`: иконка, "ты — судья", заголовок "Засчитать ответ
  {имя}?", подпись с именем, два блока side-by-side "ответ {имя}" vs
  "персонаж", строка "твой вердикт — окончательный", кнопки в порядке
  **«Отклонить» (слева, красная) → «Верно» (справа, зелёная)** — не
  наоборот, как сейчас).
- Обычный `playing` (список игроков + Да/Нет/Я знаю) показывается только
  когда НИ ОДНО из состояний выше не активно для текущего игрока (другие
  игроки, ожидающие своего вердикта/подтверждения от ДРУГОГО человека,
  по-прежнему видят обычный список — это не их полноэкранное состояние).

### B. Мобильный финал — добавить стаггер-анимацию (её сейчас нет)

Карточки результатов должны появляться по очереди снизу вверх (последнее
место первым, победитель последним), как на TV, только с чуть более
короткими интервалами (см. `Phone - Финал.html`: `.25s/.45s/.65s/.85s/1.1s/1.4s`
для 6 игроков, сжимай при большем числе).

### C. TV — точечные правки

- В шапке во время `playing` под hero-карточкой/в footer добавить строку
  «У {имя текущего игрока} на телефоне: Нет · Да · Я знаю!» (см.
  `TV - Ход игрока.html`, класс `.remote-hint`).
- В баннере оспаривания подставлять реальное имя оспаривающего игрока:
  «{Имя} оспаривает ответ» вместо текущего generic текста.
- В футере `finished` добавить «У {имя победителя} на телефоне: Играть
  снова».
- Overlay «Угадала!» — сверить с `TV - Угадала!.html`: полноэкранный
  тёмный blur-фон (`rgba(4,14,22,.66)` + `blur(16px) saturate(140%)`), сам
  тост крупнее и центрирован, с чипами «{персонаж}» и «+{очки} очков»
  отдельными пилюлями (сейчас, возможно, texту рендерится по-другому —
  сверь и приведи к макету).

### D. Общее для всех экранов

Пройдись по всем 13 файлам ещё раз и сверь: отступы карточек, радиусы
скругления, цвета текста (`--text-tertiary`/`--text-secondary` и т.п. —
бери ближайшие эквиваленты из существующей палитры проекта в
`globals.css`, не выдумывай новые), размеры аватаров, иконок, шрифтов.
Цель — чтобы результат при сравнении бок-о-бок с HTML-файлом выглядел как
тот же дизайн, а не «в похожем стиле».
