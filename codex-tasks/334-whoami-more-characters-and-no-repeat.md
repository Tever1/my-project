### 2. Анти-повтор персонажей между раундами

В `src/app/game/[roomId]/who-am-i/page.tsx`:

- Завести `const recentlyUsedRef = useRef<Set<string>>(new Set());`
  внутри компонента `WhoAmIPage` — хранит ключи персонажей (использовать
  `char.en` как уникальный ключ, он не переводится и стабилен), которые
  были в **последнем сыгранном раунде** (или двух последних — см. ниже).
- Изменить `assignCharacters` так, чтобы она принимала второй аргумент —
  множество "исключённых" ключей, и предпочитала персонажей НЕ из этого
  множества:
  ```ts
  function assignCharacters(
    playerIds: string[],
    excludeKeys: Set<string> = new Set(),
  ): Record<string, { ru: string; en: string }> {
    const preferred = WHO_AM_I_CHARACTERS.filter((c) => !excludeKeys.has(c.en));
    // Если после исключения осталось персонажей меньше, чем нужно игрокам —
    // используем полный пул (иначе будут повторы assignCharacters[i % length]
    // среди самих же игроков в одном раунде — это хуже, чем случайный повтор
    // с прошлым раундом).
    const pool = preferred.length >= playerIds.length ? preferred : WHO_AM_I_CHARACTERS;
    const shuffled = [...pool].sort(() => Math.random() - 0.5);
    const result: Record<string, { ru: string; en: string }> = {};
    playerIds.forEach((id, i) => {
      result[id] = shuffled[i % shuffled.length];
    });
    return result;
  }
  ```
- В `handleStart`, при вызове `assignCharacters(playerIds)` — передавать
  `recentlyUsedRef.current`:
  ```ts
  const characters = assignCharacters(playerIds, recentlyUsedRef.current);
  ```
  И сразу после — обновить `recentlyUsedRef.current` набором ключей ИЗ
  ЭТОГО нового раунда (`new Set(Object.values(characters).map((c) => c.en))`),
  **заменяя** (не объединяя) предыдущее содержимое — то есть "исключаем
  персонажей из непосредственно предыдущего раунда", без накопления через
  много раундов подряд (при 130 персонажах и обычно 4-8 игроках этого
  достаточно, чтобы не повторяться раунд-к-раунду, и не переусложняет
  логику долгосрочным трекингом).
- Это чисто client-side память компонента (переживает "Играть снова",
  так как страница не перемонтируется) — **не отправлять по сокету и не
  писать в `gs`**, это внутренняя эвристика хоста при выборе персонажей,
  не часть синхронизируемого состояния игры.

## Открытые вопросы для Codex

- Сколько раундов "помнить" для анти-повтора? — **Один** (только
  предыдущий раунд), как описано в шаге 2. Не нужно накапливать историю
  за много раундов — усложнение не нужно.
- Что делать при дубликате имени внутри вставляемых 100? — **Убрать
  дублирующую строку**, не придумывать замену самостоятельно, указать
  в отчёте какую убрал.
- Нужно ли это поведение синхронизировать между хостом и остальными
  игроками? — **Нет**, это только эвристика на стороне хоста в момент
  вызова `assignCharacters` — сами персонажи всё равно приходят всем
  через обычный `broadcast({ type: 'start-game', characters, ... })`,
  ничего в протоколе синхронизации не меняется.
