## Цель

Игра «Кто я?» должна переживать пропущенный/потерянный broadcast (телефон
свернули, разлочили с задержкой, TV переподключился, HMR в dev) без
необратимого рассинхрона состояния. Любой клиент (телефон ИЛИ TV), который
что-то пропустил, должен быть способен запросить полное текущее состояние
у хоста и получить его.

---

## Контекст

Баг: у пользователей после нескольких раундов игры «Кто я?» экран на
телефоне «зависает» и перестаёт обновляться — показывает устаревшую
информацию (чей ход, сколько «Да» подряд, экран угадывания и т.п.), хотя
игра на самом деле продолжается у других игроков.

**Корневая причина найдена при чтении кода** (не гипотеза — подтверждено
построчным сравнением с другими играми):

Игра «Кто я?» — **единственная из всех 7 игр, у которой вообще нет
механизма ресинхронизации состояния**. Она работает по чистой модели
"дельта-broadcast без источника истины": каждое действие
(`ask-question`, `next-turn`, `guess`, ...) применяется как *инкремент*
поверх локального `prev`-состояния через `setGs(prev => ...)`. Если
клиент (телефон или TV) пропустил хотя бы один broadcast — например,
сокет отвалился на 5-20 секунд пока телефон был заблокирован/свёрнут
(это НОРМАЛЬНОЕ поведение мобильных браузеров, задокументировано в
`CLAUDE.md` как известный подводный камень) — все следующие дельты
применяются поверх уже неверной базы, и локальное состояние клиента
расходится с реальностью НАВСЕГДА, без какого-либо способа
самовосстановиться. Чем дольше игра идёт (чем больше раундов/вопросов),
тем выше шанс, что хотя бы один телефон однажды что-то пропустил — это
и объясняет «зависает после пары кругов».

Доказательства, что это единственная игра без ресинхронизации:
- В `src/app/tv/[roomId]/[gameType]/page.tsx` есть карта
  `TV_STATE_REQUEST` (строка ~27), которая заставляет TV при подключении
  (`tv:join` callback, строка ~372-380) запросить полное состояние у
  хоста для **hundred-to-one, crocodile, alias, quiz, spy**. Ключа
  `'who-am-i'` в этой карте **нет**.
- В `src/app/game/[roomId]/who-am-i/page.tsx` тип действия
  `{ type: 'sync-state'; state: WhoAmIGameState }` и обработчик
  `case 'sync-state': setGs(payload.state); break;` (строка ~222)
  **существуют**, но их никто никогда не отправляет — это мёртвый код,
  недописанная реализация. Сравни с `quiz/page.tsx`, где есть
  симметричная пара: клиент, получивший `'quiz:request-state'`,
  ЕСЛИ он хост — отвечает `sendAction('quiz:sync', gameStateRef.current)`
  (см. `src/app/game/[roomId]/quiz/page.tsx`, case `'quiz:request-state'`
  рядом с концом `useEffect` слушателя действий). У «Кто я?» такого
  ответчика нет вообще.
- В `src/app/tv/[roomId]/[gameType]/page.tsx` у «Кто я?» тоже есть тип
  `sync-state` и case `case 'sync-state': setWhoAmIState(wp.state); break;`
  (строка ~622-623) — тоже никогда не вызывается.

Референс для копирования паттерна: **Quiz** (`quiz:request-state` /
`quiz:sync`) — самый чистый пример, один хост, один таймер, легко
сравнить 1-в-1. Crocodile/Alias/Spy — тот же паттерн под своими
префиксами (`croc:`, `alias:`, `spy:`).

- `src/app/tv/[roomId]/[gameType]/page.tsx` — TV-экран: добавить
  `'who-am-i'` в `TV_STATE_REQUEST`, чтобы TV при `tv:join` тоже запрашивал
  состояние (как остальные 5 игр).

### НЕ ТРОГАТЬ

  клиентский, как у остальных игр.
- Другие игры (`quiz`, `crocodile`, `alias`, `spy`, `hundred-to-one`,
  `mafia`) — используются только как референс для чтения, их код не
  трогать.
- `CLAUDE.md`, `AGENTS.md` — обновляет только Claude.

## Шаги реализации

1. **В `src/app/game/[roomId]/who-am-i/page.tsx`:**
   - Добавить в тип `GameAction` новый вариант
     `{ type: 'request-state' }` (используем единый action-канал
     `who-am-i`, отдельного канала типа `who-am-i:request-state` заводить
     не нужно — тут уже всё идёт через один `broadcast`/`useGameBroadcast(roomId, 'who-am-i')`,
     в отличие от quiz/crocodile у которых отдельные action-имена).
   - Завести `gsRef` (`useRef`), синхронизировать его с `gs` в `useEffect`
     (`gsRef.current = gs`) — по образцу `gameStateRef` в `quiz/page.tsx` —
     чтобы обработчик `on('game:action', ...)` мог прочитать самое свежее
     состояние без stale closure.
   - В `switch (payload.type)` добавить:
     - `case 'request-state':` — если `isGameHost` (или, если хоста
       среди игроков может не быть — просто "текущий active player"?
       **нет, строго `isGameHost`, как во всех остальных играх**) — вызвать
       `broadcast({ type: 'sync-state', state: gsRef.current })`.
   - Добавить `useEffect`, который при **первом маунте компонента** (и
     ТОЛЬКО если `gs.phase !== 'lobby'`, то есть игра уже идёт — иначе
     нет смысла запрашивать) отправляет
     `broadcast({ type: 'request-state' })`. Это покроет случай
     "открыл страницу/переподключился телефон и попал в игру, где уже
     что-то происходило".
   - **Дополнительно** (важно для основного бага — пропущенный broadcast
     ПОСЛЕ того как страница уже смонтирована, не только при маунте):
     подписаться на `socket`-уровне на восстановление соединения. Есть
     готовый паттерн в `src/lib/use-socket.ts` — при `connect` эмитится
     `player:back`, если `!document.hidden`. Самый простой правильный
     способ здесь: слушать `visibilitychange` (или проще — использовать
     уже существующий `on('connect', ...)` через `useSocket` **не
     обязательно дублировать саму подписку** — вместо этого использовать
     `document.addEventListener('visibilitychange', ...)` внутри
     `who-am-i/page.tsx` и при возврате видимости (`!document.hidden`)
     и живой игре (`gs.phase !== 'lobby'`) слать
     `broadcast({ type: 'request-state' })`. Это самое надёжное место —
     срабатывает и при разлочке телефона, и при возврате из фона,
     независимо от того, порвался сокет или нет.
2. **В `src/app/tv/[roomId]/[gameType]/page.tsx`:**
   - Добавить `'who-am-i': 'who-am-i:request-state'`? **Нет** — см. п.1,
     у «Кто я?» нет отдельного action-имени, всё идёт через один канал
     `who-am-i`/`action==='who-am-i'`. Поэтому `TV_STATE_REQUEST` для
     `who-am-i` **не подходит буквально** (там `sendAction(requestAction)`
     эмитит `game:action` с `action = requestAction` напрямую, что не
     совпадает со схемой `who-am-i`, где `action` всегда `'who-am-i'`,
     а тип действия — внутри `payload.type`).
   - Вместо правки `TV_STATE_REQUEST` — сделать явный спецкейс: после
     `tv:join` callback, если `gameType === 'who-am-i'`, вызвать
     `sendAction('who-am-i', { type: 'request-state' })` (использовать
     существующий `sendAction` — это `useGameAction(roomId)` из
     `src/lib/use-game-action.ts`, сигнатура `(action, payload)`).
     Реализовать это рядом с существующим блоком `tv:join` (строка
     ~372-380), веткой `if (gameType === 'who-am-i') { ... } else if
     (requestAction) { sendAction(requestAction); }`.
   - Обработчик `case 'sync-state': setWhoAmIState(wp.state); break;`
     (строка ~622-623) уже существует на TV — ничего менять не нужно,
     он и так корректно примет ответ хоста.
3. Прогнать мысленно (или реально через `npm run dev` + browser panel,
   если удобно) сценарий: открыть игру на 2 телефонах + TV, начать игру,
   у одного телефона имитировать пропуск (например через devtools —
   offline на пару секунд во время чужого хода, потом online) — экран
   должен подхватить актуальное состояние без ручного рефреша.

> Если по ходу выясняется, что нужен дополнительный шаг или другой файл —
> остановиться, написать в отчёт, вернуть управление Claude.

## Открытые вопросы для Codex

- Нужно ли добавлять `'who-am-i'` в `TV_STATE_REQUEST`? — **Нет**, эта
  карта предполагает отдельное action-имя типа `quiz:request-state`,
  а у «Кто я?» единый канал `action==='who-am-i'` с типом внутри
  `payload.type`. Сделать отдельную ветку, как описано в шаге 2.
- Должен ли non-host тоже уметь отвечать на `request-state` (например,
  "любой игрок, у кого состояние новее")? — **Нет**, строго `isGameHost`,
  как во всех остальных играх — иначе будет гонка нескольких
  одновременных ответов.
- Что если `isGameHost` сам является тем, кто всё пропустил (то есть
  хост тоже отстал)? — **Не блокирует этот таск.** Это edge case
  (реконнект самого хоста) — если он всплывёт в QA, будет отдельным
  тасков. Текущая цель — покрыть основной сценарий (обычный игрок
  пропустил broadcast, хост в порядке).
