# TASK-352: GameLayout — дубликат React key в скорборде при одинаковых именах

## Whitelist файлов
- `src/components/games/GameLayout.tsx`

## Баг

Console error: `Encountered two children with the same key, "3123"` — в
скорборде `GameLayout` (шапка игрового экрана, полоса с иконками игроков/
команд) ключ элемента строится по `entry.name`:

```tsx
{scores.map((entry) => {
  ...
  return (
    <div key={entry.name} ...>
```

Если у двух команд/игроков совпадает имя (например, в «100 к 1» команды
не переименовали и обе получили одинаковое дефолтное имя, или два игрока
совпали по нику), React получает два элемента с одинаковым `key` — падает
предупреждение и рендер элементов становится непредсказуемым (могут
задваиваться/пропадать).

Это общий компонент — им пользуются все 7 игр (`scores` проп передаётся из
каждой игровой страницы), баг актуален для любой игры, где имена команд/
игроков не гарантированно уникальны.

## Фикс

В `src/components/games/GameLayout.tsx`, в `scores.map((entry) => {...})`
(~строка 91), заменить построение ключа на индекс-зависимый, гарантированно
уникальный:

```tsx
{scores.map((entry, idx) => {
  ...
  return (
    <div key={`${idx}-${entry.name}`} ...>
```

То есть: добавить `idx` вторым параметром в `.map()` и использовать
`key={`${idx}-${entry.name}`}` вместо `key={entry.name}`.

## Что НЕ трогать

- Больше нигде в файле логику не менять — только сигнатуру `.map()` и
  строку с `key`.
- Проп `scores` в игровых страницах (`quiz`, `mafia`, `crocodile`, `spy`,
  `alias`, `who-am-i`, `hundred-to-one`) не трогать — фикс полностью
  локален в `GameLayout.tsx`.

## Acceptance

- Ключ элемента скорборда гарантированно уникален даже при совпадающих
  `entry.name` у разных записей.
- Порядок и визуал скорборда не меняются.
- `npx tsc --noEmit` и `npm run lint` проходят.
